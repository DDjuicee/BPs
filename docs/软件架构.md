# BPs 软件架构

日期：2026-11-06

当前程序是一个跑在浏览器里的单页应用。没有账号服务器，没有数据库。本机的开发服务器只负责把源码编译后交给浏览器，并提供谱面和音频文件。

## 1. 技术栈

| 层 | 选择 |
| --- | --- |
| 语言 | TypeScript，严格模式 |
| 界面 | React 19 |
| 构建 | Vite 6 |
| 测试 | Vitest 3，Node 环境 |
| 音频 | Web Audio API |
| 画面 | 一个 Canvas 2D |
| 设置 | `localStorage` |

生产构建命令是 `tsc --noEmit && vite build`。测试文件不参与类型检查。React 没有使用 StrictMode，避免开发时音频被启动两次。

以后的在线版本计划仍由这一个 Node 进程提供页面、接口和文件，数据放在 SQLite，上传文件放在磁盘。这一部分还没有代码。

## 2. 为什么要经过本机地址

`index.html` 只放了一个空的 `#root`，并用模块脚本指向 `src/main.tsx`。浏览器不能直接编译 TypeScript 和 JSX，也不能用 `file://` 去读这个绝对路径。

`npm run dev` 启动 Vite。它监听本机的 5173 端口，把源码编译成浏览器可执行的脚本，并把 `public/` 原样公布在网站根目录。所以游戏地址是：

`http://localhost:5173/`

`localhost` 就是这台电脑。请求不会发到外网。

## 3. 模块

```text
index.html
  └─ src/main.tsx              挂载 React
       └─ src/App.tsx          页面切换、加载谱面和音频
            ├─ src/settings.ts 流速、偏移、键位
            ├─ src/chart.ts    谱面结构和校验
            ├─ src/accuracy.ts 准确率显示
            └─ src/game/session.ts   时钟、输入、暂停、绘制循环
                 ├─ src/game/engine.ts  纯判定
                 └─ src/game/draw.ts    纯绘制

public/chart.json
public/audio.wav
scripts/generate-test-assets.mjs
```

依赖方向是单向的。`engine.ts` 只接收音符、偏移和音频时间，不读取 DOM、音频设备或 React 状态。`draw.ts` 只根据引擎状态画一帧。`session.ts` 把时钟和输入接进这两个模块。

## 4. 页面状态

`App` 有五个画面：`start`、`settings`、`loading`、`play`、`result`。

Play 被点击时才创建 `AudioContext`，并在这次用户操作里恢复它。然后并行请求 `/chart.json` 和 `/audio.wav`，请求不使用缓存。音频用 `decodeAudioData` 解码，谱面用解码后的时长做校验。失败则关闭音频上下文并回到开始页。成功则替换上一局的资源，并关闭旧的音频上下文。

`PlayScreen` 在谱面资源和设置不变时只挂载一次游戏。结算和退出回调放在 ref 里，暂停造成的重渲染不会把音频重新开始。Retry 只增加局号，复用已经解码的资源。

## 5. 时钟

主时钟是 `AudioContext.currentTime`，不是动画帧的时间戳。

```text
音频时间 = (当前音频上下文时间 - 锚点) × 1000 + 锚点上的音频时间
```

开局时，锚点上的音频时间是负的出现时间。缓冲从 0 开始播放，并安排到时钟走到 0 的那一刻。因此判定线以上先走出一段预备，时间为 0 的音符从顶端进入。

暂停记下当前音频时间并停止音源。继续时把锚点改到“暂停点减去出现时间”，预备期间 `judging` 为假。时钟走到暂停点后恢复判定，并按当时的按键状态补一次结算。

动画帧只负责推进判定和绘制。按下和松开在事件到达时读取音频时间并立刻判定。

## 6. 判定引擎

`createEngine` 把谱面抄成运行时音符。单键的尾部状态是 `none`。长按的头部和尾部各自是 `pending`，结算后变成 `perfect`、`good` 或 `miss`。

四个入口：

| 函数 | 职责 |
| --- | --- |
| `press` | 选择本轨最早的开窗音符，结算头部 |
| `release` | 结算正在按住的尾部 |
| `advance` | 处理已经松开的轨、超时 MISS、长按连击、按住超过尾巴后窗口 |
| `forceResolve` | 音频结束并超过 150 毫秒后，把剩余音符全部记为 MISS |

`dt` 的定义见《产品需求》。窗口常量集中在 `engine.ts` 顶部：`PERFECT_MS = 60`，`GOOD_MS = 130`，`EARLY_MISS_MS = 200`，`TAIL_EARLY_MS = 80`，`TAIL_LATE_MS = 200`。长按尾部在到达谱面时间时不立刻结算；仍按住且超过尾巴 200 毫秒后才自动记 GOOD。

松开键时的顺序是：

1. 先 `advance`，但本帧不把仍按住的尾部自动结算。这样连击 tick 不会漏掉。
2. 把该键标成松开，调用 `release`。尾巴前 80 毫秒到尾巴后 200 毫秒内松开记 PERFECT，更晚松开记 GOOD。
3. 再 `advance` 一次。其他长按若仍按住，并且已经晚于尾巴 200 毫秒，记 GOOD。

头部 MISS 会在同一次结算里把尾部也写成 MISS。提前松开时，`ghostChartTime = 音频时间 - 偏移`，绘制用它把剩余长按改成空心条。

分数和连击只在 `applyGrade` 里改变。长按 tick 直接增加连击，不调用它，因此不改变分数和判定计数。

## 7. 绘制

设计分辨率是 400×800。画布的像素宽高乘上 `devicePixelRatio`，再用 `setTransform` 把坐标系缩回去。CSS 让画布填满那条 90vh 的竖栏。

音符纵坐标：

```text
y = 700 × (1 - (谱面时间 + 偏移 - 音频时间) / 出现时间)
```

判定线以上的区域被裁剪。判定文字保留 500 毫秒，时间同样用音频时钟计算。

## 8. 输入和持久化

键名在进入游戏前就确定。对局里把 `event.key` 规范成小写字母、数字，或空格、分号、逗号、句号，再映射到四条轨道。Esc 单独处理。`event.repeat` 被忽略。

设置写成 JSON，键名 `bps-settings`。读到缺字段、重复键或非法键时回到默认值：流速 3.0、偏移 0、键位 D F J K。

## 9. 测试资源

`npm run generate` 生成 14 秒、44100 Hz、单声道 16 位 WAV，以及同名测试谱。谱面标题是 Test，录音名是 Local test tone。共 27 颗音符，其中 2 条长按、25 颗单键。满分 2900。全部完美时最大连击是 54，包括单键、长按头尾和按住期间的 tick。

判定测试直接调用引擎，不启动浏览器。测试覆盖窗口边界、偏移、同轨先打早的音符、长按提前松开、头部 MISS 连带尾部、按住到尾巴、整谱满分，以及准确率截断。

## 10. 在线版本的预定边界

社区功能仍然放在这个站点后面，不另起一个前端项目。页面、上传接口和排行榜由同一个 Node 进程提供。账号和成绩进 SQLite。音频和谱面文件留在磁盘。下架只停止发音频和阻止新成绩，不删除页面和已有排行榜。

第一阶段的判定引擎可以继续作为纯模块被服务端复用；服务端不需要复用 Canvas 和 React。
